# V7C.10 bounded neutral control-loop characterization

This separately invoked engineering harness uses only PW-6h and qualified
shared-bootstrap block #1. It does not run a treatment comparison, select a
compression factor/duration, acquire another bootstrap or change V8 semantics.
`python -m dynapm.system_validation.neutral_characterization run-two` runs exactly
two serial bounded probes, stopping on failure, with no automatic retry. Each has
a new kind cluster, Pod/application, profile process, controller/collector state,
request generator and startup identities. Existing containers are preserved; an
occupied engine fails preflight. Cached pinned node and original workload images
are required. The qualified artifact and qualification SHA are verified; original
artifact files are checked again after the probe. Fresh source must be committed.

Live request rate, iterations, seed and persistent workset use unchanged stable
workload settings. The first actuator target is the production PW-6h consumer's
recommendation from the qualified initialization. Subsequent targets are an
explicit engineering ladder, not claimed as PW-6h profile outcomes: CPU/memory
increases, decreases, one-dimensional changes, repeated/no-op targets and a large
consecutive transition. The target list, 240s active bound, 60s per-resize bound,
0.2s observation polling and descriptive 20-response window are fixed in code
before observing these runs. These engineering limits are not compression slots
or criteria for accepting compressed scientific outcomes.

A short execution cannot naturally observe a genuine six-hour PW-6h refresh.
For every opportunity the profile process times the actual production trailing
24h selection, forecast and four-field commit on a disposable PW-6h policy copy.
This isolated component bypasses due/eligibility scheduling and is labelled as
such. The live policy retains one initialization and zero runtime refreshes;
no synthetic observations enter its history. Actual scheduling/eligibility of a
compressed trace is not established by this benchmark.

Each relevant event records host-local monotonic timing and wall provenance:
complete telemetry response/admission, profile component computation,
recommendation, patch submit/ack, independent Pod response and cgroup-envelope
receipt bounds, one in-flight pending interval, explicitly skipped adjacent
opportunities and decision-to-enforcement time. CPU and memory convergence are
separate. First observed matches are polling-dependent upper bounds, not kernel
event times. API acknowledgement never establishes enforcement.

After enforcement the generator continues unchanged. Already in-flight request
drain, persistent workset, post-enforcement response latencies and a fixed
20-response observation window are retained. Pod/cgroup agreement is rechecked
before the next actuator target. This is mechanical/descriptive settling evidence,
not a statistical steady-state claim or an acceptance tolerance invented from
favorable outcomes. Missing/censored dimensions are not replaced with zero.

Host guards keep the existing AC/open-lid, adapter, owned assertions, boot,
2-second wall/monotonic and 30-second heartbeat-gap requirements. No preflight
exception from the old acquisition is inherited. Source, artifacts, qualification,
images, environment, stimuli, requests and raw timing/clock/host evidence belong
to managed non-claim runs under ignored `results/neutral_characterization`.

V7C.11 must prospectively define any candidate physical durations and acceptance
criteria. In particular, unchanged scientific telemetry still requires >=50
samples and >=270s physical receipt span in a complete host-time 300s bucket.
Fast kernel actuation alone cannot justify shortening this scientific clock or
coverage contract. Decision computation, actuation, polling uncertainty, drain,
unestablished statistical settling and no overlapping/pending carryover all
constrain any future proposal. No compressed execution is implemented here.
